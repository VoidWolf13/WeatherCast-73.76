# Правила проекта

WeatherCast 73.76 — генератор аудиопрогноза погоды для радиоэфира
(Ростов-на-Дону).

## 1. Портативность

Где запустил — там и работает. Никаких абсолютных путей и внешних настроек:
все ресурсы (ffmpeg/ffprobe, piper и его DLL, модели голосов, фон) внутри
сборки; `config.json`, `runstate.json` и `ПОГОДА.wav` пишутся рядом с exe.
Перенос — копированием папки. `config.json` — настройки (пишет GUI),
`runstate.json` — служебный журнал прогонов (пишут GUI и CLI, см. п. 7).

## 2. Максимальная надёжность

Вывод идёт в радиоэфир, поэтому:
- сбой одного синтезатора не валит эфир — цепочка идёт к следующему;
- числа заранее переводятся в слова (TTS не читает цифры);
- готовый файл проверяется по длительности и размеру.

## 3. Синтезаторы

Порядок приоритета по умолчанию:
**Edge TTS (Microsoft) → gTTS (Google) → Piper (офлайн).**
Набор и порядок задаются в интерфейсе. Piper — офлайн-резерв.
Голоса: Edge — Dmitry/Svetlana; gTTS — русский; Piper — denis/dmitri/irina/ruslan.

## 4. Целевая платформа

Windows 10 x64, сборка onedir (PyInstaller). Сборка и автотест — через Wine
на хосте, финальный тест — в ВМ Win10.

## 5. Эфирный формат

Фон `assets/WEATHER_2023_IIII.wav` + голос с задержкой 4 с, голос чуть громче
фона; результат — `ПОГОДА.wav`.

## 6. Создание аудиофайла «ПОГОДА»

1. Данные берём из сети (Open-Meteo) и формируем текст по образцу
   (`docs/EXAMPLE-TEXT.md`) и правилам (`docs/TEXT-RULES.md`).
2. Синтезируем голос одним из движков (Edge TTS / gTTS / Piper).
3. Накладываем голос на фон `assets/WEATHER_2023_IIII.wav` с задержкой 4 с;
   голос немного громче фона (BG_VOLUME 0.35, VOICE_VOLUME 1.0).
4. Готовый файл сохраняем как `ПОГОДА.wav` рядом с программой (путь задаётся в UI).
5. Длительность голоса подгоняем под фон: сокращение текста по приоритету,
   затем ускорение не более +15 % (atempo <= 1.15).

## 7. Запуск в ВМ

Frozen-сборку нельзя запускать прямо с virtiofs-шары (диск D:) — загрузчик
PyInstaller падает («pyimod02_importers is NULL»). Запускать через
`ЗАПУСК_ПРОГРАММЫ.bat`: он копирует сборку на локальный диск гостя
(`%LOCALAPPDATA%\WeatherCast-73.76`) и стартует оттуда.

## 8. Расписание и журнал прогонов

Расписание можно отрабатывать двумя способами, и они не должны мешать друг
другу:

1. **Из GUI** — таймер раз в 20 с проверяет слоты, запускает синтез;
2. **Из планировщика Windows** — `WeatherCast-73.76.exe --run --slot HH:MM`.

Чтобы запуск из планировщика был виден в интерфейсе, а слот не срабатывал
дважды, обе стороны пишут исход в общий `runstate.json` (не в `config.json`):

- `last_run` — исход последнего прогона; из него GUI берёт статус-строку;
- `slot_results` — исход по каждому времени (отметки в строках расписания);
- `fired` — «слот `YYYY-MM-DD HH:MM` уже сработал»: `mark_slot()` ставится
  до старта, поэтому ни повторный запуск, ни ручной пуск в ту же минуту
  не дают дубль в эфире.

Если слот уже отработал, CLI не падает, а отвечает
`{"ok": false, "skipped_slot": "HH:MM"}` и кодом возврата 0 — планировщик
не должен считать это ошибкой.

Коды возврата `WeatherCast-73.76.exe --run --slot HH:MM`:

| Код | Значение |
|---|---|
| 0 | файл создан **или** слот уже отработал (штатный пропуск) |
| 1 | ошибка синтеза (смотрите `weather.log`) |
| 2 | некорректный аргумент слота |

### Батник `ПОГОДА_ПО_РАСПИСАНИЮ.bat`

Лежит в корне сборки. Делает три шага: обновляет рабочую копию на локальном
диске гостя (обход virtiofs), вызывает exe с `--run --slot`, возвращает
`runstate.json` / `ПОГОДА.wav` / `weather.log` в сборку.

```bat
ПОГОДА_ПО_РАСПИСАНИЮ.bat 09:00   :: конкретный слот
ПОГОДА_ПО_РАСПИСАНИЮ.bat         :: текущее время (проверка)
```

Без батника exe тоже работает, но падает на virtiofs — поэтому в планировщик
ставим именно батник, а не exe.

### Регистрация в планировщике Windows

В ВМ Win10 от имени администратора (путь подставьте свой — где лежит сборка):

```bat
schtasks /create /tn "WeatherCast 09:00" /sc daily /st 09:00 ^
  /tr "\"%LOCALAPPDATA%\WeatherCast-73.76\ПОГОДА_ПО_РАСПИСАНИЮ.bat\" 09:00" /f
```

Пять слотов (06:00 / 09:00 / 12:00 / 15:00 / 18:00) — пять отдельных задач:
расписание в интерфейсе и планировщик Windows независимы, связывает их только
общий `runstate.json`. Дублирования не будет: слот отмечается до старта.

Проверка и удаление:

```bat
schtasks /query /tn "WeatherCast 09:00" /v /fo list
schtasks /run   /tn "WeatherCast 09:00"      :: прогнать сейчас
schtasks /delete /tn "WeatherCast 09:00" /f
```

Задача запускается от текущего пользователя и только при входе в систему
(галочка «Выполнять только при входе пользователя»). Для выпуска без входа
потребуется хранить пароль — на боевой машине это решает void.

## 9. Страница проекта на GitHub

Публичная страница — <https://github.com/VoidWolf13/WeatherCast-73.76>.
**Правило: при каждой правке кода следить и за страницей — README и раздел
Releases должны соответствовать текущему состоянию.** Расхождения вводят
в заблуждение того, кто пришёл за программой.

Что проверять при выпуске версии:

1. **Раздел «Скачать» в README** — ссылка на `releases/latest` и имя архива
   с версией. Должна быть в начале файла, а не в конце.
2. **Релиз помечен Latest.** `gh release create` с `--prerelease` делает
   релиз предварительным: GitHub не показывает его в боковой панели, и там
   остаётся только «1 tag / Create a new release». Готовую сборку помечать
   `--latest`, без `--prerelease`.
3. **Архив приложен** и его имя в описании релиза совпадает с фактическим.
4. **Версия в README/описании** совпадает с `VERSION`.

Быстрая проверка глазами посетителя:

```bash
gh release list                                   # Latest ли
gh api repos/VoidWolf13/WeatherCast-73.76/readme \
  --jq .content | base64 -d | head -20            # что видно на странице
gh api repos/VoidWolf13/WeatherCast-73.76/releases/latest \
  --jq '{tag:.tag_name, prerelease:.prerelease}'
```
