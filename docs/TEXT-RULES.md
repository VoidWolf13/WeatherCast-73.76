# Правила формирования текста прогноза
WeatherCast 73.76 — Ростов-на-Дону
Актуально на 12.10.2026. Согласовано с weather.py (функция build_text).

НАЗНАЧЕНИЕ
Текст идёт в радиоэфир: должен звучать естественно, укладываться в отведённое
время и одинаково читаться любым из трёх синтезаторов (Edge TTS, gTTS, Piper).
Все числа заранее переводятся в слова.

1. ИСТОЧНИК ДАННЫХ
Open-Meteo. Хосты перебираются по порядку (поле API_HOSTS):
historical-forecast-api -> api.open-meteo -> ensemble-api.
Запрос: current (температура, weather_code, ветер и его направление, давление msl,
влажность); hourly (температура, weather_code, ветер, порывы, давление, влажность);
daily (мин/макс температуры, weather_code, господствующее направление ветра).
Ветер — в метрах в секунду (wind_speed_unit=ms), иначе Open-Meteo отдаёт км/ч.
Часовой пояс — Europe/Moscow, глубина — 2 суток.

2. ЧИСЛА В СЛОВА (обязательно)
- Температура: «пятнадцать», «минус пять». Слово «плюс» НЕ проговаривается;
  «минус» — только для отрицательных.
- Диапазон температуры: «от восемнадцати до двадцати» — через «от … до …»,
  а не через тире (тире TTS читает как обрыв).
- Ветер: одно значение — «два метра в секунду»; диапазон —
  «от шести до одиннадцати метров в секунду».
- Порывы: «порывы до четырнадцати метров в секунду» (единицы обязательны).
- Давление: «семьсот пятьдесят восемь миллиметров ртутного столба» (гПа x 0.750062).
- Влажность: «шестьдесят девять процентов».
- Склонения обязательны: градус/градуса/градусов, метр/метра/метров,
  процент/процента/процентов, миллиметр/миллиметра/миллиметров.

3. НАПРАВЛЕНИЕ ВЕТРА НЕ НАЗЫВАЕТСЯ
В эфире звучит только скорость ветра; направление из данных не озвучивается.

4. ПОГОДНЫЕ КОДЫ (WMO)
Словарь WMO в коде: 0 «ясно», 1 «преимущественно ясно», 2 «облачно с
прояснениями», 3 «пасмурно», 45/48 «туман», 51/53/55 «морось», 56/57 «ледяная
морось», 61 «небольшой дождь», 63 «дождь», 65 «сильный дождь», 66/67 «ледяной
дождь», 71 «небольшой снег», 73 «снег», 75 «сильный снег», 77 «снег»,
80/81/82 ливневый дождь, 85/86 снег, 95 «гроза», 96/99 «гроза с градом».
Неизвестный код -> безопасно «переменная облачность». Если осадков нет —
добавляем «без осадков».

5. ПОРЯДОК БЛОКОВ В ТЕКСТЕ (новый, с 12.10.2026)
  1) Сейчас:  «В Ростове-на-Дону сейчас … градусов, ….», только температура + погода.
  2) Сегодня (9:00–19:00): «Сегодня днём ожидается … градусов, ….», затем
     «Ветер … .», затем «Относительная влажность … .», затем «Атмосферное давление … .»
  3) Ночью (21:00–07:00): «Ночью ожидается … градусов, ….», температура + погода,
     затем (низший приоритет) «Относительная влажность … .» и
     «Атмосферное давление … .».
  4) Завтра: «Завтра … градусов, ….», затем (низший приоритет) отдельное
     предложение про осадки ЗА ДЕНЬ (9:00-19:00, ночь не учитывается):
     «Возможен дождь/снег/гроза.» либо «Без осадков.», затем (низший приоритет)
     «Относительная влажность … .» и «Атмосферное давление … .».
Внутри «Сегодня», «Ночью» и «Завтра» порядок деталей: ветер -> влажность -> давление.

6. ПРИОРИТЕТЫ (что режется при нехватке времени; меньшее число — важнее)
  0 — «сейчас» (ядро, не режется)
  1 — температура+погода дня / ночи / завтра
  2 — ветер (день)
  3 — влажность (день)
  4 — давление (день)
  5 — осадки завтра за ДЕНЬ 9:00-19:00 («Возможен дождь/снег/гроза» или «Без осадков»)
  6 — влажность (ночь и завтра)
  7 — давление (ночь и завтра)
Детали (ветер, влажность, давление) — низкий приоритет; при сокращении текста
они уходят первыми, чтобы все 4 основных блока (сейчас/сегодня/ночью/завтра)
уместились в эфир. Приоритеты 6–7 добавлены 14.10.2026: заполняют эфир при
запасе времени, чтобы не оставалось пустоты в конце; режутся самыми первыми.

7. ДЛИНА И ПОДГОНКА
Голос должен уложиться в фон минус вступление (4 с) и запас 0.5 с
(около 30 с при текущем фоне). Если длиннее — текст режется по приоритету, затем
при необходимости ускоряется не более чем на +15 % (atempo не выше 1.15).

8. ПОДАЧА ТЕКСТА СИНТЕЗАТОРАМ
Все три движка получают текст целиком: список предложений склеивается пробелом
и уходит одним запросом (Edge TTS, gTTS, Piper — единообразно). Ручная разбивка
на фразы и склейка не применяются. Паузы между предложениями расставляет сам
движок. Предложения всё равно держим короткими (8–12 слов).

9. ИСКЛЮЧЕНИЯ
Недоступный параметр — пропускаем. Код погоды вне словаря — «переменная
облачность». Сбой одного синтезатора не валит эфир: цепочка переходит к
следующему (Edge TTS -> gTTS -> Piper).
