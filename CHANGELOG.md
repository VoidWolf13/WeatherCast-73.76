Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — [Semantic Versioning](https://semver.org/lang/ru/).

Записи о версиях 0.1–0.9 носят ретроспективный характер: система
версионирования введена 13.10.2026, поэтому ранние номера отражают этап,
а не точную сборку.

## [0.21.1] — 2026-10-16

### Added
- **Проверка формата `--slot`** (`weather.valid_slot`): раньше аргумент
  принимался как есть и мусорное значение попадало и в ключ `fired`, и в
  `slot_results`, а планировщик считал запуск успешным. Теперь формат
  `HH:MM` (00–23 / 00–59) проверяется до старта: при ошибке — сообщение
  и код возврата 2, отметок в `runstate.json` не появляется.
- **Консольный режим боевого exe.** `WeatherCast-73.76.exe --run --slot HH:MM`
  (и `--selftest`, `--show-config`) теперь работает без окна: раньше GUI-сборка
  с `console=False` эти аргументы игнорировала — планировщик открывал окно,
  а файл не создавался. Разбор флагов — в `weather_gui.main()`, дальше вызов
  `weather.cli()`. Тот же exe, что и в окне, — второй сборки не нужно.
- **`ПОГОДА_ПО_РАСПИСАНИЮ.bat`** — запуск выпуска по расписанию: обновляет
  рабочую копию на локальном диске гостя (обход virtiofs), вызывает exe с
  `--run --slot`, возвращает `runstate.json` / `ПОГОДА.wav` / `weather.log`
  в сборку. Время берётся из аргумента или из текущего момента.

### Changed
- GUI-проверка времени слота `_valid_time` больше не дублирует разбор:
  вызывает тот же `weather.valid_slot`, что и CLI, — одно правило на оба
  входа. Разбор стал строже: `7:30` принимается, `12:34:56` — нет.

## [0.21.0] — 2026-10-16

### Added
- **`runstate.json` — общий журнал прогонов** для GUI и CLI. Раньше исход
  запуска лежал в `config.json`, который пишет только интерфейс, поэтому
  запуск из планировщика Windows по CLI не был виден в окне, а слот мог
  сработать дважды. Теперь обе стороны пишут в одно место через
  `weather.record_run()`:
  - `last_run` — исход последнего прогона (успех/ошибка, движок, что
    пропущено) — статус-строка GUI читает его оттуда;
  - `slot_results` — исход по каждому времени расписания;
  - `fired` — отметка «слот `YYYY-MM-DD HH:MM` уже сработал».
- **`weather.py --run --slot HH:MM`** — запуск по расписанию из командной
  строки (планировщик Windows): проверяет `fired`, пишет исход в
  `runstate.json`. Если слот уже отработал, отвечает
  `{"ok": false, "skipped_slot": "HH:MM"}` и кодом возврата 0 — для
  планировщика это не ошибка, а штатный пропуск.

### Changed
- GUI больше не хранит `last_run` и `slot_results` в `config.json`:
  `config.json` — только пользовательские настройки (путь, синтезаторы,
  расписание), служебное состояние — в `runstate.json`. Старые ключи из
  существующего `config.json` игнорируются, файл чистить не нужно.
- Флаг «слот сработал» переехал из памяти процесса GUI в `runstate.json`,
  поэтому перезапуск приложения больше не приводит к повторному эфиру
  в ту же минуту.

## [0.15.1] — 2026-10-14

### Fixed
- На чужом ПК программа не могла получить прогноз: `Open-Meteo недоступен:
  <urlopen error _ssl.c:993: The handshake operation timed out>`. Причина —
  Python предпочитает AAAA-запись (IPv6), и там, где IPv6-маршрут «висит»,
  SSL-handshake не укладывался в таймаут 20 с. Теперь сначала пробуется IPv4
  (`_urlopen_ipv4`, подмена `socket.getaddrinfo` на `AF_INET`), затем штатный
  порядок — чтобы работать и в IPv6-only сети. Проверено живым запросом.

Разбор дизайнера (второй скриншот): слои читаются, кнопки белые с рамкой.
Докрутка по чек-листу из 10 пунктов.

### Changed
- Расписание: убран дублирующий значок ⓘ — осталась только цветная точка-светофор
  слева от времени (зелёный/жёлтый/красный/серый по статусу). Один акцент в окне.
- Статус-строка: «3/3» → «3/3 синт.», имя файла убрано (дублировало поле пути).
- ▲▼ — прозрачные icon-кнопки (`objectName="arr"`) с hover-подсветкой.

- Прогресс: белый текст поверх цветного чанка во всех состояниях работы.

### Added
